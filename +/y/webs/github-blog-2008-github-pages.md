## Resumen util

La entrada original del blog de GitHub sobre Pages, publicada en diciembre de 2008, explica la idea fundacional del servicio con una frase muy potente para el manual: publicar contenido web podia volverse tan simple como hacer `git push`. La nota tambien muestra que desde el comienzo coexistieron dos usos pedagogicamente interesantes: paginas personales ligadas al nombre de usuario y paginas de proyecto publicadas desde una rama `gh-pages`.

Tambien es util la explicacion de por que GitHub eligio una rama separada para muchas paginas de proyecto: evitar ensuciar el directorio principal del codigo y mantener clara la separacion entre fuente del proyecto y sitio publicado.

## Datos puntuales aprovechables

- La nota original se publico el 18 de diciembre de 2008.
- GitHub describio Pages como una forma de publicar contenido web tan simple como hacer `git push`.
- Para sitios personales bastaba un repositorio `username.github.com`.
- Para muchos proyectos se uso la rama `gh-pages` como espacio de publicacion separado.
- El post presenta Pages como una forma de crear documentacion y sitios colaborables con la misma logica del codigo.

## Posibles usos en el manual

- abrir el tutorial de GitHub Pages con una anecdota historica;
- explicar por que publicar desde el repositorio no es una idea reciente sino fundacional;
- orientar a estudiantes sobre la separacion entre archivos del proyecto y rama o flujo de publicacion.
