## Resumen util

La documentacion de GitHub Projects define un proyecto como una tabla, tablero y roadmap adaptable que se integra con issues y pull requests para planificar y seguir trabajo. Esa definicion es muy valiosa para el capitulo 11 porque transforma la idea de "avance verificable" en una practica concreta de organizacion del proyecto dentro del mismo repositorio.

Ademas, la pagina muestra que un proyecto puede combinar vistas, campos personalizados, automatizaciones e insights sin imponer una unica metodologia. Eso encaja con la tesis del capitulo: un proyecto legaltech serio no necesita teatralidad tecnica, pero si necesita estructura, trazabilidad y criterio.

## Datos puntuales aprovechables

- GitHub Projects integra seguimiento de trabajo con issues y pull requests.
- Ofrece vistas de tabla, board y roadmap.
- Permite agregar metadatos propios mediante campos personalizados.
- Puede automatizar cambios y generar visualizaciones o insights del trabajo.

## Posibles usos en el manual

- sugerir una forma concreta de documentar proyectos finales o grupales;
- reforzar la idea de trazabilidad entre problema, tareas, avances y repositorio;
- mostrar que gestionar un proyecto tambien es una competencia tecnica basica.
