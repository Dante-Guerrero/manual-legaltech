7. HTML, CSS y JavaScript para una presencia web básica

NoteQué aprenderás en esta sesión

Esta sesión toma una idea central del módulo y la vuelve práctica: no basta con navegar la web; conviene entender cómo se construye una página sencilla. A través de una breve historia material de internet, de una explicación básica sobre servidores y nube, y de ejercicios progresivos de HTML, CSS y JavaScript, el objetivo es aprender a distinguir infraestructura, estructura, apariencia e interacción, y advertir por qué una presencia digital básica también forma parte de la alfabetización profesional del jurista.

Internet también tiene una historia material

Con frecuencia hablamos de internet como si fuera una nube abstracta suspendida en ninguna parte. Pero la red tiene una materialidad mucho más concreta. Durante décadas, la conexión global ha dependido sobre todo de grandes cables submarinos y terrestres que rodean el mundo, enlazan continentes y transportan volúmenes inmensos de información entre ciudades, centros de datos y proveedores. Cuando alguien abre una página, envía un correo o consulta un expediente en línea, buena parte de ese recorrido suele pasar por infraestructura física tendida bajo el océano o enterrada en tierra firme.

Esa historia no se ha detenido. En los últimos años se ha vuelto más visible otra capa complementaria: el internet satelital. No reemplaza por completo a los cables, pero sí amplía cobertura en zonas difíciles, remotas o menos atendidas por redes terrestres. Por eso conviene mirar el presente con algo de precisión: internet sigue descansando sobre cables de enorme importancia estratégica, pero al mismo tiempo incorpora más conectividad apoyada en satélites. La red, en otras palabras, no es un solo sistema homogéneo, sino una combinación de infraestructuras que transportan información de maneras distintas.

Compartir información, archivos y servicios

En su forma más básica, internet consiste en permitir que computadoras distintas compartan información a distancia. A veces esa información viaja como mensajes, a veces como video, a veces como bases de datos, y muchas veces como archivos. La web es una de las formas más visibles de ese intercambio: una computadora solicita un recurso y otra responde entregando contenido. En páginas sencillas, ese contenido suele empezar por un archivo HTML, al que luego pueden sumarse hojas de estilo CSS, scripts JavaScript, imágenes y otros recursos (MDN Web Docs 2026a, 2026b).

Ese detalle importa porque devuelve la web a algo muy concreto. Cuando visitas un sitio, no estás entrando en un espacio mágico. Estás pidiendo archivos y recibiendo archivos. El navegador toma ese material, lo interpreta y lo convierte en una página legible. Por eso aprender HTML no es solo aprender una sintaxis: es entender la forma más básica en que la web comparte contenido.

Servidores, cloud y presencia en línea

Para que esos archivos puedan entregarse a otras personas, alguien debe alojarlos y servirlos. Allí aparece el rol del servidor: una máquina o servicio preparado para responder solicitudes y entregar contenido cuando un navegador lo pide. Si tu archivo index.html está solo en tu laptop, existe como archivo local. Si ese mismo archivo se aloja en un servidor accesible por internet, puede convertirse en una página pública.

La nube o cloud no elimina esta lógica; la reorganiza. En lugar de depender siempre de una sola máquina identificable y gestionada por una organización concreta, muchos servicios cloud permiten alojar archivos, aplicaciones y datos en infraestructura remota más flexible, distribuida y escalable. Eso desplaza parte del control técnico, pero no elimina las responsabilidades sobre acceso, seguridad y tratamiento de la información (Presidencia del Consejo de Ministros 2021). En términos pedagógicos, basta con retener una idea: cuando subes una página a GitHub Pages o a otro servicio similar, sigues publicando archivos desde servidores reales, aunque la infraestructura se te presente como servicio en la nube.

La web también se escribe

Una parte importante del trabajo jurídico contemporáneo ya circula por interfaces que otras personas diseñaron: formularios, portales, sitios institucionales, páginas de estudios, servicios de consulta y repositorios públicos. Mientras esos entornos solo se usan como consumidor, parecen una superficie ya dada. Pero cuando se observa cómo están hechos, aparece otra intuición: una página web no es un espacio abstracto, sino una combinación de archivos, etiquetas, estilos y pequeñas reglas de comportamiento (MDN Web Docs 2026a, 2026b).

Ese cambio de mirada importa en una facultad de Derecho por una razón sencilla. Entender lo mínimo de HTML, CSS y JavaScript no busca formar desarrolladores frontend, sino volver menos opaca la infraestructura más cotidiana de publicación digital. Una página personal, una ficha profesional, un formulario o una pequeña interfaz informativa pueden bastar para mostrar cómo se organiza contenido, cómo se presenta y cómo reacciona ante quien la usa.

Estructura, apariencia e interacción

La separación entre HTML, CSS y JavaScript conviene entenderla desde el principio porque ordena todo el capítulo:

  • HTML define la estructura del contenido;
  • CSS controla la apariencia visual;
  • JavaScript agrega comportamiento e interacción.

La utilidad pedagógica de esta división es inmediata. Obliga a no mezclar funciones. Si una página no se entiende, suele haber un problema de estructura. Si se entiende pero se ve mal, el problema suele ser visual. Si se ve bien pero no responde a la acción del usuario, el problema está en el comportamiento. Esa separación ayuda a pensar con más claridad también cuando después se usan herramientas más complejas.

Antes de entrar al código

Antes de empezar con los ejercicios conviene ordenar bien la expectativa. Este capítulo no presupone experiencia previa en desarrollo web. La idea no es que memorices todas las etiquetas o propiedades, sino que entiendas una secuencia simple y repetible: escribir un archivo, guardarlo, abrirlo en el navegador, observar qué cambió y volver al editor para ajustar una parte pequeña. Aprender web al inicio consiste sobre todo en acortar esa distancia entre lo que escribes y lo que ves.

También conviene trabajar con una lógica acumulativa. Primero verás HTML, porque sin estructura no hay página. Luego aparecerá CSS, porque una estructura sin estilo sigue siendo difícil de leer. Después entrará JavaScript, porque una página bien escrita y bien presentada todavía puede ser completamente estática. Si mantienes clara esa progresión, los ejercicios dejan de sentirse como piezas sueltas y empiezan a formar un recorrido comprensible.

ImportantAntes de empezar

Para trabajar esta sesión basta con una carpeta simple y un navegador. Lo más cómodo es usar una estructura como esta:

  • index.html para el archivo principal;
  • style.css cuando quieras separar estilos;
  • script.js cuando quieras mover el comportamiento fuera del HTML.

Una forma especialmente cómoda de hacer esto es trabajar los archivos en Visual Studio Code, porque te permite abrir la carpeta completa, editar HTML, CSS y JavaScript en el mismo espacio y luego abrir o recargar el resultado en el navegador. Si todavía no tienes ese entorno listo, conviene revisar el tutorial Visual Studio Code.

Cada ejercicio de este capítulo puede abrirse directamente en el navegador. La recomendación práctica es avanzar en orden, modificar una o dos líneas y recargar la página después de cada cambio. Si algo no cambia en pantalla, conviene revisar tres cosas antes de seguir: si el archivo quedó guardado, si abriste el archivo correcto y si el navegador recargó la versión más reciente.

Una rutina útil para toda la sesión puede resumirse así:

  1. crear o abrir un archivo;
  2. copiar un ejemplo corto;
  3. guardar;
  4. abrir o recargar en el navegador;
  5. observar el resultado;
  6. volver al editor y cambiar un detalle pequeño.

Esa disciplina evita un problema muy frecuente: copiar mucho código sin llegar a entender qué parte produjo qué efecto visible.

HTML: dar forma al contenido

Ejercicio 1. La primera página: título y párrafo

El punto de partida más sobrio consiste en ver que una página ya existe cuando tiene una estructura mínima reconocible. Este primer archivo no hace mucho, pero enseña algo decisivo: todo lo visible en pantalla nace de etiquetas que indican qué tipo de contenido hay en cada lugar (MDN Web Docs 2026a).

Copia este código en un archivo como 00-hola-mundo.html:

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Hola mundo</title>
  </head>
  <body>
    <h1>Hola, mundo</h1>
    <p>Esta es mi primera pagina web.</p>
  </body>
</html>

Aquí ya aparecen varias piezas fundacionales:

  • <!DOCTYPE html> declara el tipo de documento;
  • <html> envuelve toda la página;
  • <head> contiene metadatos;
  • <body> reúne lo visible;
  • <h1> marca el título principal;
  • <p> introduce un párrafo.

La utilidad del ejemplo no está en su espectacularidad, sino en mostrar que una página se compone de partes con jerarquía. Esa misma lógica reaparecerá en páginas más complejas.

Cómo se ve esto en el navegador

El punto decisivo es distinguir entre el archivo y su resultado visible. El navegador no muestra las etiquetas como texto normal. Las interpreta y las convierte en una página.

● ● ●
00-hola-mundo.html

Hola, mundo

Esta es mi primera pagina web.

La diferencia parece simple, pero enseña algo fundamental. HTML describe la estructura del contenido y el navegador decide cómo presentarla. El h1 aparece como encabezado principal; el p aparece como párrafo. Cuando abras el archivo en el navegador, no verás “código fuente”, sino la interpretación visual de ese código.

Ejercicio 2. Organizar información con títulos y secciones

Cuando la página deja de ser un simple saludo, la pregunta cambia: ya no basta con mostrar algo, sino que conviene ordenarlo. Los títulos y subtítulos sirven justamente para eso.

Copia este archivo:

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Texto y titulos</title>
  </head>
  <body>
    <h1>Introduccion al derecho digital</h1>
    <h2>Que estudia</h2>
    <p>Estudia los efectos de la tecnologia en las normas, procesos y relaciones entre personas.</p>
    <h2>Por que importa</h2>
    <p>Ayuda a entender temas como privacidad, contratos electronicos y firma digital.</p>
  </body>
</html>

La transición importante aquí es conceptual. HTML no sirve solo para “poner texto”, sino para indicar jerarquías. Un h1 no cumple la misma función que un h2, y esa diferencia importa para legibilidad, accesibilidad y organización del contenido.

Cómo se ve esto en el navegador

Si abres este archivo, verás un título principal y, debajo, dos bloques de contenido más pequeños.

Ejercicio 3. Listas, enlaces y tablas como formas de trabajo

Una parte significativa del trabajo jurídico se presenta como colección de elementos: tareas, documentos, citas, requisitos o registros. Por eso conviene ver tres estructuras muy comunes: listas, enlaces y tablas.

Lista y enlace

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Listas y enlaces</title>
  </head>
  <body>
    <h1>Tareas de hoy</h1>
    <ul>
      <li>Leer una resolucion</li>
      <li>Ordenar expedientes</li>
      <li>Enviar un correo</li>
    </ul>

    <p>
      Puedes buscar mas informacion en
      <a href="https://developer.mozilla.org/es/" target="_blank" rel="noreferrer">MDN en espanol</a>.
    </p>
  </body>
</html>

Tabla simple

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Tabla simple</title>
  </head>
  <body>
    <h1>Registro de citas</h1>
    <table border="1">
      <tr>
        <th>Persona</th>

En estos ejemplos HTML deja ver algo más cercano al trabajo real: una lista sirve para agrupar elementos del mismo tipo, un enlace conecta la página con otro recurso y una tabla organiza información en filas y columnas. Aunque los ejemplos son pequeños, ya aparecen formas de representación muy útiles para portales, fichas y paneles sencillos.

Ejercicio 4. Formularios: capturar información

La web no solo publica; también recibe datos. Por eso los formularios son una pieza central de muchos servicios digitales.

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Formulario simple</title>
  </head>
  <body>
    <h1>Formulario de contacto</h1>
    <form>
      <label for="nombre">Nombre</label>
      <input id="nombre" type="text" placeholder="Escribe tu nombre">

      <br>
      <br>

      <label for="correo">Correo</label>
      <input id="correo" type="email" placeholder="correo@ejemplo.com">

      <br>
      <br>

      <label for="mensaje">Mensaje</label>
      <br>
      <textarea id="mensaje" rows="4" cols="30"></textarea>

      <br>
      <br>

      <button type="submit">Enviar</button>
    </form>
  </body>
</html>

La enseñanza del ejemplo no está en enviar el formulario, sino en reconocer los bloques básicos de entrada: label, input, textarea y button. Muchos servicios jurídicos digitalizados dependen precisamente de esta lógica de captura estructurada.

Cómo se ve esto en el navegador

Al abrirlo, verás un pequeño formulario: una etiqueta para Nombre, una caja de texto, otra para Correo, un área grande para Mensaje y un botón Enviar.

CSS: volver legible la página

Una página correctamente estructurada puede seguir viéndose pobre o confusa. Allí entra CSS: no cambia qué cosa es cada bloque, pero sí cómo se presenta (MDN Web Docs 2026b). Eso importa porque en interfaces jurídicas y profesionales la legibilidad también forma parte de la calidad del servicio.

Ejercicio 5. Primeros estilos: fuente, fondo y color

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>CSS basico</title>
    <style>
      body {
        font-family: Arial, sans-serif;
        background-color: #f4f7fb;
        margin: 0;
        padding: 24px;
      }

      h1 {
        color: #1d3557;
      }

      p {
        color: #444;
        line-height: 1.6;
      }
    </style>
  </head>
  <body>
    <h1>Pagina con estilos</h1>
    <p>CSS permite cambiar la apariencia de una pagina web.</p>
  </body>
</html>

Este archivo muestra una primera decisión importante: CSS puede escribirse dentro de <style> cuando el ejemplo es pequeño. El resultado visible suele ser inmediato. Cambia la tipografía, aparece un fondo y el texto gana legibilidad. La estructura sigue siendo la misma, pero la experiencia de lectura ya no es equivalente.

Cómo se ve esto en el navegador

Sin CSS, el navegador mostraría algo muy simple: un título negro, un párrafo estándar y fondo blanco. Con las reglas anteriores, el resultado visible cambia de inmediato.

La utilidad de esta comparación está en que permite aislar el papel de CSS. El contenido sigue siendo exactamente el mismo. Lo que cambia es la forma en que se presenta: color, espacio y legibilidad.

Ejercicio 6. Colores, cajas y espaciado

Cuando una página necesita destacar un mensaje o separar un bloque del resto, entra en juego el modelo de caja. Eso significa pensar en ancho, margen, relleno y bordes.

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Cajas y espaciado</title>
    <style>
      body {
        font-family: Arial, sans-serif;
        background: #faf8f2;
      }

      .tarjeta {
        width: 320px;
        margin: 40px auto;
        padding: 20px;
        border: 2px solid #caa56a;
        background: white;
      }
    </style>
  </head>
  <body>
    <div class="tarjeta">
      <h1>Expediente 204</h1>
      <p>Esta tarjeta muestra como funciona el espacio interno y externo de un bloque.</p>
    </div>
  </body>
</html>

La clase .tarjeta enseña algo fundamental: el contenido no solo se escribe, también se encierra en bloques visuales. Esa idea será útil después para fichas, avisos, paneles y formularios.

Si lo abres en el navegador, no verás solo un texto suelto. Verás una especie de ficha o tarjeta centrada, con fondo blanco, borde visible y espacio interior. Ese efecto importa porque muestra que CSS no se limita a “pintar”; también organiza bloques y les da presencia visual.

Ejercicio 7. Tipografía y flexbox

El estilo también sirve para ordenar visualmente varios elementos a la vez. En el material base de esta sesión aparecen dos movimientos muy útiles: mejorar la tipografía y usar flexbox para alinear cajas en fila.

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Flexbox basico</title>
    <style>
      body {
        font-family: Arial, sans-serif;
        padding: 24px;
      }

      .fila {
        display: flex;
        gap: 16px;
      }

      .bloque {
        flex: 1;
        padding: 20px;
        background: #dbeafe;
        border: 1px solid #60a5fa;
      }
    </style>
  </head>
  <body>
    <h1>Panel de accesos</h1>
    <div class="fila">
      <div class="bloque">Agenda</div>
      <div class="bloque">Clientes</div>
      <div class="bloque">Pagos</div>
    </div>
  </body>
</html>

Aquí el aprendizaje ya no es solo estético. display: flex permite distribuir elementos en una misma fila con una lógica mucho más controlable que el simple apilamiento vertical. Para interfaces simples, esta técnica basta para construir paneles bastante claros.

En el navegador, la diferencia es muy visible: en lugar de aparecer una caja debajo de la otra, Agenda, Clientes y Pagos quedan alineadas horizontalmente como accesos de un pequeño panel. Eso deja ver que CSS también sirve para decidir cómo se acomodan los elementos entre sí.

JavaScript: hacer que la página responda

Hasta aquí la página muestra contenido y se ve mejor, pero sigue siendo estática. JavaScript introduce comportamiento: permite reaccionar, calcular, leer entradas y cambiar lo que aparece en pantalla.

Ejercicio 8. El primer script

El primer paso conviene mantenerlo pequeño: comprobar que el navegador ya puede ejecutar instrucciones.

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Script basico</title>
  </head>
  <body>
    <h1>Abre la consola del navegador</h1>

    <script>
      console.log("Hola desde JavaScript");
    </script>
  </body>
</html>

El mensaje no aparece en la página, sino en la consola del navegador. Ese detalle es útil porque enseña a distinguir entre lo que el usuario ve y lo que el desarrollador usa para comprobar que el código está funcionando.

En pantalla, por tanto, solo verás el texto Abre la consola del navegador. La acción de JavaScript ocurre fuera de la página visible y se comprueba en la consola. Ese primer paso es deliberado: antes de modificar la interfaz, conviene comprobar que el lenguaje ya está corriendo.

Ejercicio 9. Variables y condicionales

Una vez que el script corre, puede guardar información y tomar decisiones.

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Condicionales</title>
  </head>
  <body>
    <h1>Estado de pago</h1>
    <p id="resultado"></p>

    <script>
      const deuda = 0;
      let mensaje = "";

Ejercicio 10. Bucles, funciones y eventos

Tres ideas del material de referencia merecen quedar juntas porque forman una secuencia muy natural:

  • un bucle repite una acción sobre varios elementos;
  • una función encapsula una operación reutilizable;
  • un evento espera la acción de la persona usuaria.

DOM y formularios: leer lo que la persona escribe

El siguiente paso consiste en conectar JavaScript con campos reales de la página. Allí aparece el DOM, es decir, la forma en que el navegador representa internamente el documento para que pueda ser leído y modificado.

Ejercicio 11. Leer un input y mostrar un saludo

<!DOCTYPE html>
<html lang="es">
  <head>
    <meta charset="UTF-8">
    <title>Leer input</title>
  </head>
  <body>
    <h1>Saludo personalizado</h1>
    <input id="nombre" type="text" placeholder="Escribe tu nombre">
    <button id="mostrar">Mostrar saludo</button>
    <p id="salida"></p>

    <script>
      const boton = document.getElementById("mostrar");
      const salida = document.getElementById("salida");

      boton.addEventListener("click", function () {
        const nombre = document.getElementById("nombre").value;
        salida.textContent = "Hola, " + nombre;
      });
    </script>
  </body>
</html>

La novedad aquí es el uso de .value, que permite leer lo que una persona escribió en un campo. La página deja de ser una pieza cerrada y empieza a reaccionar a una entrada externa.

En el navegador verás una caja para escribir tu nombre, un botón y un espacio vacío. Si escribes Lucía y haces clic, el espacio vacío pasa a mostrar Hola, Lucía. Esa escena, tan simple, contiene una idea central de toda interfaz web: leer una entrada y devolver una salida visible.

Dos ejercicios del repositorio base ayudan a cerrar esta etapa: revisar si un campo está vacío y modificar visualmente un bloque desde un evento.

Validación simple

<input id="correo" type="email" placeholder="correo@ejemplo.com">
<button id="enviar">Validar</button>

<script>
  const boton = document.getElementById("enviar");

Conclusiones del capítulo

Aprender una base de HTML, CSS y JavaScript cambia la relación con la web porque vuelve visible su materialidad mínima. Una página deja de parecer un contenedor mágico y empieza a verse como una estructura de contenido, una capa de estilo y una serie de comportamientos simples pero controlables. Para estudiantes de Derecho, esa alfabetización no es ornamental. Ayuda a entender mejor el entorno donde hoy se presentan servicios, perfiles, formularios e información pública.

TipIdeas clave
  • HTML organiza el contenido y le da jerarquía.
  • CSS mejora legibilidad, disposición y apariencia visual.

  • Los formularios muestran cómo la web captura y procesa entradas del usuario.
